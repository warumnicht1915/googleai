# 배포 검증

대상: ImageSearch 1.2.0 (핫링크 차단 극복, 삭제 기능).

## 통과한 것

- 자동 테스트 **54개** 통과 (`pytest -q`, Python 3.11 / Qt 6.11.2 offscreen).
  - **Referer 사다리**: 페이지 Referer를 거부하고 자기 호스트만 허용하는 로컬 서버에서 복구되는지, Referer가 아예 없어야만 허용하는 경우까지 내려가는지, 픽시브 같은 알려진 호스트에 맞는 Referer가 먼저 나가는지
  - **거부와 오류의 구분**: 모든 Referer가 거부되면 일반 오류가 아니라 브라우저 폴백을 요청하는 신호를 보내는지
  - **브라우저가 받아온 파일 인수**: 이미지인지 검증하고 확장자를 붙여 저장하는지, HTML 같은 차단 페이지가 오면 임시 파일까지 정리하며 실패하는지
  - **삭제**: 원본만 지우면 좋아요·카테고리·미리보기가 남는지, 파일이 이미 사라졌을 때 목록 기록을 고쳐 주는지, 라이브러리에서 제거하면 파일·행·카테고리 연결이 모두 사라지는지
  - 미리보기가 썸네일이 아니라 원본에서 만들어지는지, 1600px 초과만 축소되는지, 투명도가 유지되는지
  - 추가 페이지의 중복 제거와 종료 조건, 취소·다른 검색어의 늦은 응답 무시
  - 두 테마의 팔레트 토큰 일치, 아이콘 번들 존재, 슬롯 안에서 예외가 새면 실패하는 애니메이션 테스트
  - 화면 픽셀 비율 렌더링, 작은 원본 과확대 금지, 120장 목록의 지연 로딩
- **`scripts/verify_browser_fetch.py` 실증**: 쿠키가 있어야만 이미지를 주는 로컬 호스트를 세워, 일반 HTTP 경로가 거부되는 것과 앱 내 Chromium이 같은 파일을 바이트 단위로 동일하게 받아오는 것을 한 번에 확인했습니다.
- 통제된 로컬 HTML로 추출 로직 검증 (`verify_search.py`), 자동 수집 흐름 검증 (`verify_auto_search.py`).
- 문서 스크린샷은 **빈 임시 데이터 폴더**로 실행한 실제 앱 화면입니다 (`scripts/capture_ui.py`). 개인 라이브러리·검색 기록·계정이 포함되지 않으며, 표시된 이미지는 합성 픽스처입니다.

## 검증하지 못한 것

- **실제 픽시브·트위터 등에서의 다운로드 성공.** Referer 규칙과 브라우저 폴백은 통제된 로컬 서버로만 검증했습니다. 실제 사이트는 봇 차단·로그인·지역 제한이 추가로 걸릴 수 있고, **모든 이미지를 받을 수 있다고 보장하지 않습니다.**
- **실제 Google 실검색의 전체 성공.** 개발 네트워크에서 Google이 CAPTCHA를 요구해 끝까지 확인하지 못했습니다. 스크롤 페이징도 기록된 응답으로만 검증했습니다.
- **SerpApi 실계정 호출.** 개인 API 키가 없어 실행하지 않았습니다.
- **macOS 앱 번들.** 이번 수정본은 macOS 머신에서 직접 빌드하지 못했습니다. 배포 앱은 `release-macos.yml` 워크플로가 태그에서 Intel·Apple Silicon 두 가지로 빌드합니다.
- **Windows / Linux 실행** 은 확인하지 않았습니다.
- 애니메이션은 정지 화면과 예외 감시로만 확인했습니다. 움직임 자체는 자동 검증 대상이 아닙니다.
